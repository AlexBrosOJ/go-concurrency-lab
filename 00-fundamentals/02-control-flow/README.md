# Управление выполнением в Go

## Цель модуля

Управление выполнением (control flow) определяет, какие инструкции выполняются, в каком порядке и при каких условиях.

В этом модуле мы подробно разберём:

- `if`, `else if`, `else`;
- логические операторы и короткое замыкание вычислений;
- `switch` и его варианты;
- циклы `for`;
- `break` и `continue`;
- `range` для перебора коллекций и строк;
- вложенные циклы и метки;
- `defer` и порядок выполнения отложенных вызовов.

Все примеры находятся в одном файле `main.go`. Читай его последовательно и экспериментируй с условиями, значениями и границами циклов.

## Как запустить

Из корня репозитория:

```bash
go run ./00-fundamentals/02-control-flow
```

## 1. Условные конструкции: if / else if / else

Условные конструкции позволяют выполнять разные участки кода в зависимости от результата проверки.

```go
func grade(score int) string {
    if score >= 90 {
        return "A"
    }
    if score >= 75 {
        return "B"
    }
    if score >= 60 {
        return "C"
    }
    return "F"
}

score := 82
fmt.Println("Grade:", grade(score))
```

Go проверяет условия последовательно сверху вниз. Выполняется тело первой ветки, условие которой истинно. Если ни одно условие не сработало, выполняется `else`, если он присутствует.

Для `score = 82` результатом будет `Grade: B`.

Важные особенности:

- Условие должно иметь тип `bool`.
- Круглые скобки вокруг условия не требуются.
- Фигурные скобки обязательны.
- `else` относится к ближайшей подходящей конструкции `if` и записывается вместе с закрывающей скобкой предыдущей ветки.
- После выполнения одной из веток остальные ветки этой конструкции не проверяются.

### Частая ошибка: неправильный порядок условий

Предположим, мы сначала проверили `score >= 60`, а затем `score >= 90`. При значении `95` первая проверка уже окажется истинной, поэтому программа не дойдёт до проверки на `90`.

Поэтому условия обычно располагают от наиболее специфичных к более общим.

## 2. Объявление переменной внутри if

Go позволяет объявлять переменную в короткой инструкции перед условием:

```go
if number := 15; number%2 == 0 {
    fmt.Println(number, "is even")
} else {
    fmt.Println(number, "is odd")
}
```

Здесь `number := 15` — короткая инструкция, а `number%2 == 0` — условие.

Переменная доступна внутри условия и соответствующих веток `if`/`else`, но не за пределами всей конструкции.

Это удобно, если значение нужно только для одной проверки. Так мы ограничиваем область видимости и не оставляем лишние переменные в окружающем коде.

## 3. Логические операторы и короткое замыкание

Основные логические операторы:

| Оператор | Значение |
|---|---|
| `&&` | И: оба условия должны быть истинными |
| `||` | ИЛИ: достаточно одного истинного условия |
| `!` | НЕ: меняет логическое значение на противоположное |

Пример:

```go
age := 25
hasExperience := true

if age >= 18 && hasExperience {
    fmt.Println("Candidate meets the basic requirements")
}
```

Оператор `&&` требует истинности обеих частей выражения.

### Короткое замыкание

Go использует short-circuit evaluation: если результат уже определён по первой части выражения, вторая часть не вычисляется.

Для `&&` это происходит, когда первая часть ложна. Для `||` — когда первая часть истинна.

```go
value := 0

if value != 0 && 100/value > 1 {
    fmt.Println("Condition is true")
}
```

Поскольку `value != 0` ложно, деление на ноль не происходит: правая часть выражения не вычисляется.

Это полезно, например, при проверке указателя на `nil` перед обращением к его полям или при проверке длины коллекции перед обращением к элементу.

## 4. Конструкция switch

`switch` позволяет выбрать одну из нескольких веток без длинной цепочки `if / else if`.

```go
day := "Saturday"

switch day {
case "Monday", "Tuesday", "Wednesday", "Thursday", "Friday":
    fmt.Println("Working day")
case "Saturday", "Sunday":
    fmt.Println("Weekend")
default:
    fmt.Println("Unknown day")
}
```

Go вычисляет выражение `switch` и сравнивает его с вариантами `case`. В примере выходные объединены в один `case`.

`default` выполняется, если ни один вариант не подошёл.

### Важное отличие от C и C++

В обычном `switch` в Go после выполнения подходящего `case` выполнение не переходит автоматически к следующему `case`. Поэтому явный `break` обычно не нужен.

Инструкция `fallthrough` существует, но намеренно передаёт выполнение следующему `case` без проверки его условия. Она применяется редко, и использовать её стоит только тогда, когда такое поведение действительно необходимо.

### Switch без выражения

```go
temperature := 28

switch {
case temperature < 0:
    fmt.Println("Freezing")
case temperature < 20:
    fmt.Println("Cold")
case temperature < 30:
    fmt.Println("Warm")
default:
    fmt.Println("Hot")
}
```

Если выражение после `switch` отсутствует, каждый `case` может выступать самостоятельным логическим условием. По смыслу это похоже на последовательность `if / else if`.

Проверки идут сверху вниз. Для значения `28` сработает `temperature < 30`, потому что предыдущие условия ложны.

## 5. Цикл for

В Go существует одно ключевое слово для циклов — `for`. Оно поддерживает несколько форм.

### Классический цикл

```go
for i := 1; i <= 5; i++ {
    fmt.Println(i)
}
```

В этой конструкции три части:

1. Инициализация: `i := 1`.
2. Условие продолжения: `i <= 5`.
3. Пост-оператор: `i++`.

Инициализация выполняется один раз. Затем проверяется условие, выполняется тело цикла, после чего выполняется пост-оператор. Цикл повторяется, пока условие истинно.

Если условие изначально ложно, тело не выполнится ни разу.

### Цикл с одним условием

```go
counter := 1

for counter <= 3 {
    fmt.Println(counter)
    counter++
}
```

Такой цикл похож на `while` в других языках. В Go отдельного ключевого слова `while` нет.

Изменение `counter` находится внутри тела. Если забыть увеличить значение или другим способом сделать условие ложным, цикл может стать бесконечным.

### Бесконечный цикл

```go
for {
    // Выполняется, пока цикл не будет прерван.
}
```

Бесконечные циклы встречаются в обработчиках событий, серверных циклах и системах, которые постоянно получают и обрабатывают задачи. Выход обычно организуется с помощью `break`, `return` или других механизмов управления завершением.

## 6. break и continue

Обе инструкции изменяют обычный ход выполнения цикла, но делают это по-разному.

### break

`break` немедленно прекращает выполнение ближайшего охватывающего цикла или `switch`.

```go
for i := 1; i <= 10; i++ {
    if i > 3 {
        break
    }

    fmt.Println(i)
}
```

Будут выведены числа `1`, `2`, `3`. Когда `i` станет равен `4`, цикл завершится.

### continue

`continue` пропускает оставшуюся часть текущей итерации и переходит к следующей.

```go
for i := 1; i <= 10; i++ {
    if i%2 == 0 {
        continue
    }

    fmt.Println(i)
}
```

В результате будут выведены нечётные числа от `1` до `9`.

В классическом цикле `for` после `continue` выполняется пост-оператор, а затем снова проверяется условие. Это важно учитывать, чтобы не создать бесконечный цикл.

## 7. Перебор коллекций с помощью range

`range` позволяет перебирать элементы коллекций и других поддерживаемых типов данных.

### Слайс

```go
numbers := []int{10, 20, 30, 40}

for index, value := range numbers {
    fmt.Printf("index=%d value=%d\n", index, value)
}
```

Для слайса `range` возвращает индекс и значение элемента.

Если индекс не нужен, можно использовать пустой идентификатор `_`:

```go
for _, value := range numbers {
    fmt.Println(value)
}
```

Пустой идентификатор означает, что возвращаемое значение намеренно игнорируется. В Go нельзя объявить переменную и оставить её неиспользованной, поэтому `_` применяется довольно часто.

### Важная особенность: значение элемента — не сам элемент

```go
for _, value := range numbers {
    value = 0
}
```

В этом примере элементы слайса не обнулятся. Переменная `value` получает копию значения очередного элемента.

Чтобы изменить элемент, используй индекс:

```go
for i := range numbers {
    numbers[i] = 0
}
```

Этот вариант меняет элементы исходного слайса.

### Карта

```go
ages := map[string]int{
    "Alice": 25,
    "Bob":   30,
}

for name, age := range ages {
    fmt.Println(name, age)
}
```

Для карты `range` возвращает ключ и значение.

Порядок обхода карты не гарантирован. Не следует рассчитывать, что ключи будут возвращаться в порядке объявления или в алфавитном порядке.

Если нужен определённый порядок, ключи необходимо получить отдельно и отсортировать.

### Строка

```go
word := "GoЖ"

for index, r := range word {
    fmt.Printf("index=%d rune=%c codepoint=%U\n", index, r, r)
}
```

Строка в Go представляет собой последовательность байтов. При обходе строки через `range` цикл декодирует UTF-8 и возвращает:

- индекс первого байта очередного символа в исходной строке;
- значение типа `rune`, представляющее декодированную кодовую точку Unicode.

Поэтому индексы для `G`, `o` и `Ж` будут `0`, `1` и `2`, а не `0`, `1` и `2` по количеству байтов: символ `Ж` в UTF-8 занимает два байта, и его байтовый индекс равен `2`.

Если нужен обход каждого байта, используй обычный цикл по индексам строки. Если нужно количество кодовых точек Unicode, можно применить `utf8.RuneCountInString`. Количество кодовых точек при этом не всегда совпадает с количеством пользовательских символов: составные символы могут включать несколько кодовых точек.

## 8. Вложенные циклы и метки

Циклы могут находиться внутри других циклов. Обычный `break` завершает только ближайший цикл.

Если нужно выйти сразу из нескольких вложенных циклов, можно использовать метку:

```go
outer:
for i := 1; i <= 3; i++ {
    for j := 1; j <= 3; j++ {
        if i == 2 && j == 2 {
            break outer
        }
    }
}
```

`outer` — метка, привязанная к внешнему циклу. Инструкция `break outer` завершает именно этот цикл, поэтому управление переходит к первой инструкции после него.

Метки полезны в отдельных алгоритмах с вложенными циклами, но не стоит применять их повсюду. Иногда вынесение логики в отдельную функцию делает код проще.

## 9. defer

`defer` откладывает вызов функции до завершения окружающей функции.

```go
func example() {
    defer fmt.Println("First")
    defer fmt.Println("Second")

    fmt.Println("Body")
}
```

Результат:

```text
Body
Second
First
```

Отложенные вызовы выполняются в порядке LIFO — последним зарегистрированным выполняется первым.

### Когда вычисляются аргументы

Аргументы отложенного вызова вычисляются в момент выполнения инструкции `defer`, а не в момент фактического вызова.

```go
value := 10
defer fmt.Println(value)

value = 20
```

Отложенный вызов выведет `10`, потому что аргумент был вычислен при регистрации `defer`.

Если отложить вызов анонимной функции, которая обращается к переменной из внешней области видимости, функция может прочитать её более позднее значение. Это зависит от того, как именно написан отложенный вызов.

### Где применяется defer

`defer` часто используется для освобождения ресурсов и выполнения завершающих действий:

- закрытия файла через `Close`;
- освобождения блокировки через `Unlock`;
- закрытия тела HTTP-ответа, когда это необходимо;
- завершения измерения времени или логирования.

При работе с мьютексом распространённый шаблон — вызвать `Lock()`, а затем сразу зарегистрировать `defer Unlock()`. Это помогает не забыть снять блокировку при обычном выходе из функции.

Важно: `defer` не выполняется при аварийном завершении процесса, например при `os.Exit`. Также при панике отложенные вызовы обычно выполняются во время раскрутки стека, если процесс не прекращён принудительно.
