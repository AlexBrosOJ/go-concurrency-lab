
# Collections and Memory in Go

В этом модуле разбираем основные коллекции Go и то, как они работают с памятью.

После изучения модуля нужно понимать:

- чем массив отличается от слайса;
- что такое `len` и `cap`;
- как работает `append`;
- почему изменение одного слайса может изменить другой;
- когда `append` использует существующий массив, а когда выделяет новый;
- как работает `copy`;
- как устроены map на уровне использования;
- почему `len(string)` не равен количеству символов;
- чем `byte` отличается от `rune`.

Запуск:

```bash
go run .
```

## 1. Arrays

Массив — это последовательность элементов фиксированной длины одного типа.

```go
var numbers [3]int
```

В данном случае:

- тип массива — `[3]int`;
- длина — `3`;
- все элементы изначально равны нулю.

Массив можно заполнить сразу:

```go
numbers := [3]int{10, 20, 30}
```

Длина массива является частью его типа.

```go
var a [3]int
var b [4]int
```

`[3]int` и `[4]int` — разные типы.

### Массивы являются значениями

При присваивании массив копируется:

```go
original := [3]int{10, 20, 30}
copied := original

copied[0] = 999

fmt.Println(original) // [10 20 30]
fmt.Println(copied)   // [999 20 30]
```

Это важное отличие массива от слайса.

## 2. Slices

Слайс — это удобное представление последовательности элементов, построенное поверх массива.

```go
numbers := []int{10, 20, 30}
```

У слайса есть три важных свойства:

- указатель на область базового массива;
- длина (`len`);
- вместимость (`cap`).

Упрощённо можно представить слайс так:

```text
Slice
 ├── pointer → backing array
 ├── len
 └── cap
```

Это концептуальная модель, а не точное описание внутреннего ABI Go.

### len и cap

`len` — количество элементов, доступных через слайс.

`cap` — количество элементов от начала слайса до конца его доступной области в базовом массиве.

```go
numbers := make([]int, 3, 5)

fmt.Println(len(numbers)) // 3
fmt.Println(cap(numbers)) // 5
```

Слайс имеет длину 3, поэтому напрямую обратиться к `numbers[3]` нельзя:

```go
// panic: index out of range
// fmt.Println(numbers[3])
```

Но можно добавить элементы через `append`.

```go
numbers = append(numbers, 40, 50)

fmt.Println(numbers) // [0 0 0 40 50]
```

### nil slice и пустой slice

```go
var a []int
b := []int{}
```

Оба слайса имеют длину 0, но:

```go
fmt.Println(a == nil) // true
fmt.Println(b == nil) // false
```

Оба варианта можно использовать с `append`, `len`, `range`.

Нулевое значение слайса — `nil`.

## 3. Создание слайса через make

Форма:

```go
slice := make([]int, length, capacity)
```

Например:

```go
numbers := make([]int, 3, 5)
```

Получаем слайс длиной 3 и вместимостью 5.

Если capacity не указать:

```go
numbers := make([]int, 3)
```

то capacity будет равна length.

`make` создаёт и инициализирует слайс. Для обычного слайса элементы будут заполнены нулевыми значениями типа.

## 4. Слайсы могут разделять один backing array

Рассмотрим:

```go
original := []int{10, 20, 30, 40}

first := original[1:3]
second := original[2:4]
```

Оба слайса ссылаются на части одного базового массива.

```text
Backing array:
index:     0    1    2    3
value:    10   20   30   40
               └ first ┘
                    └ second ┘
```

Изменение элемента через `first` может быть видно через `original` и `second`:

```go
first[1] = 999

fmt.Println(original) // [10 20 999 40]
fmt.Println(first)    // [20 999]
fmt.Println(second)   // [999 40]
```

Это одна из самых важных особенностей слайсов.

Слайс — не самостоятельная копия массива. Он может ссылаться на общую память.

## 5. Как работает append

`append` добавляет элементы в слайс:

```go
numbers := []int{1, 2, 3}
numbers = append(numbers, 4)
```

Важно присваивать результат обратно:

```go
numbers = append(numbers, 4)
```

Потому что `append` возвращает новый заголовок слайса. Он может ссылаться как на прежний массив, так и на новый.

### Сценарий 1: capacity хватает

```go
base := make([]int, 3, 5)

first := base
second := base

first = append(first, 40)
```

Вместимость позволяет добавить элемент без выделения нового backing array.

`first` получает длину 4. У `second` длина остаётся 3, но он всё ещё ссылается на тот же массив.

Можно увидеть добавленное значение, расширив `second` в пределах capacity:

```go
fmt.Println(second[:4])
```

### Сценарий 2: capacity не хватает

```go
numbers := make([]int, 3, 3)
numbers = append(numbers, 4)
```

Слайсу нужно больше места. Go выделяет новый backing array, копирует туда элементы и добавляет новый.

После этого исходные слайсы, если они существовали, могут продолжить ссылаться на старый массив.

**Не полагайся на конкретный коэффициент роста capacity.** Это деталь реализации, а не гарантированный контракт языка.

## 6. copy

`copy` копирует элементы из одного слайса в другой:

```go
source := []int{10, 20, 30}
destination := make([]int, len(source))

count := copy(destination, source)
```

`copy` возвращает количество скопированных элементов.

Копируется не больше, чем позволяет длина меньшего из двух слайсов.

```go
destination := make([]int, 2)
count := copy(destination, source)
```

В этом случае будут скопированы только два элемента.

После копирования слайсы не обязаны разделять память. Если `destination` был создан отдельно, изменение его элементов не меняет `source`.

Когда результат должен гарантированно иметь независимый backing array, память нужно выделить до копирования:

```go
func cloneAndAppend(source []int, value int) []int {
    result := make([]int, len(source)+1)
    copy(result, source)
    result[len(source)] = value
    return result
}
```

Такой подход не вызывает `append` на исходном слайсе, поэтому не изменяет даже скрытую за `len` часть его backing array при наличии свободной capacity. Изменения результата и источника также не влияют друг на друга.

## 7. Full slice expression

Обычный slicing:

```go
slice := numbers[low:high]
```

Можно также указать максимальный индекс:

```go
slice := numbers[low:high:max]
```

Тогда capacity результирующего слайса будет ограничена:

```go
numbers := make([]int, 3, 5)

limited := numbers[0:2:2]

fmt.Println(len(limited)) // 2
fmt.Println(cap(limited)) // 2
```

Если добавить элемент:

```go
limited = append(limited, 99)
```

у `limited` не останется свободной capacity, поэтому `append` выделит новый массив.

Это полезно, когда нужно предотвратить случайное изменение общей области памяти через append.

## 8. range по слайсу

```go
numbers := []int{10, 20, 30}

for _, value := range numbers {
    value *= 2
}
```

Переменная `value` получает копию элемента. Поэтому изменения `value` не меняют исходный слайс.

Для изменения элементов используй индекс:

```go
for i := range numbers {
    numbers[i] *= 2
}
```

Теперь изменения будут видны в `numbers`.

## 9. Maps

Map — коллекция пар ключ-значение.

```go
ages := map[string]int{
    "Alice": 25,
    "Bob":   30,
}
```

Тип map:

```go
map[KeyType]ValueType
```

Ключ должен быть сравнимым типом. Например, строки, числа и массивы с сравнимыми элементами могут быть ключами. Слайсы, map и функции ключами быть не могут.

### Чтение

```go
age := ages["Alice"]
```

Если ключ отсутствует, map возвращает zero value типа значения.

Для проверки наличия ключа используют `comma-ok`:

```go
age, exists := ages["Charlie"]
```

- `age` — значение или zero value;
- `exists` — существует ли ключ.

Это важно, когда zero value является допустимым значением.

### Добавление, изменение, удаление

```go
ages["Charlie"] = 35
ages["Alice"] = 26

delete(ages, "Bob")
```

### Nil map

```go
var ages map[string]int
```

Из `nil` map можно читать:

```go
fmt.Println(ages["unknown"])
```

Но запись вызовет panic:

```go
// panic: assignment to entry in nil map
// ages["Alice"] = 25
```

Для записи map нужно инициализировать:

```go
ages := make(map[string]int)
ages["Alice"] = 25
```

### Порядок обхода

Порядок итерации map не гарантирован:

```go
for key, value := range ages {
    fmt.Println(key, value)
}
```

Не стоит строить логику программы на конкретном порядке элементов.

Также обычная map не предназначена для безопасных конкурентных записей из нескольких goroutine. Для такой задачи нужно синхронизировать доступ.

## 10. Strings, bytes и runes

Строка в Go — неизменяемая последовательность байтов.

```go
text := "Привет"
```

UTF-8 использует переменное количество байтов для кодирования символов.

Поэтому:

```go
fmt.Println(len(text))
```

`len` возвращает количество байтов, а не количество Unicode code points.

### byte

`byte` — псевдоним `uint8`.

```go
bytes := []byte("hello")
```

Слайс байтов удобно использовать для работы с данными, представленными байтами.

### rune

`rune` — псевдоним `int32`, обычно используется для представления Unicode code point.

```go
runes := []rune("Привет")
```

`[]rune` позволяет работать с Unicode code points, но не обязательно с визуальными символами в полном смысле. Например, некоторые emoji состоят из нескольких code points.

### range по строке

```go
for index, char := range text {
    fmt.Printf("%d %c\n", index, char)
}
```

При обходе строки через `range`:

- `index` — индекс первого байта UTF-8 последовательности;
- `char` — rune.

Индекс не является порядковым номером rune.

### Строки неизменяемы

Нельзя изменить отдельный байт строки напрямую:

```go
// text[0] = 'H' // compile error
```

Если нужно модифицировать данные, можно преобразовать строку в `[]byte` или `[]rune`, изменить слайс и преобразовать обратно.

## Практические задания

1. Создай массив из пяти чисел и скопируй его. Измени один элемент копии и проверь, изменился ли оригинал.
2. Создай слайс с `make`, у которого `len = 2`, `cap = 5`. Добавь три элемента и выведи `len` и `cap`.
3. Создай два слайса, которые ссылаются на один backing array. Измени элемент через один слайс и проверь второй.
4. Покажи пример, когда `append` меняет общий backing array, и пример, когда выделяется новый.
5. Скопируй слайс через `copy`. Измени копию и проверь оригинал.
6. Создай nil map. Проверь чтение и объясни, почему запись в неё приводит к panic.
7. Напиши функцию, которая считает количество rune в строке, не используя `utf8.RuneCountInString`.
8. Напиши функцию удаления элемента слайса по индексу. Подумай, что происходит с элементами после удалённого.

## Что важно запомнить

- Массив имеет фиксированную длину и копируется целиком при присваивании.
- Слайс — представление участка backing array.
- `len` — количество доступных элементов, `cap` — доступная вместимость.
- Слайсы могут разделять одну область памяти.
- `append` может использовать прежний массив или выделить новый.
- `copy` копирует элементы, а не делает слайсы связанными.
- Map нужно инициализировать перед записью.
- `len(string)` считает байты, а не руны.

### 1. Понимание

Когда присваивание копирует элементы, если сравнить массив `[2]int` и слайс `[]int`?

<details>
<summary>Показать ответ и объяснение</summary>

У массива копируется само значение вместе с элементами. У слайса копируется описание участка массива. Два таких описания могут обращаться к одному базовому массиву.

</details>

### 2. Вывод кода

Что напечатает этот фрагмент?

```go
base := make([]int, 1, 2)
base[0] = 7
extended := append(base, 9)
fmt.Println(len(base), extended, base[:2])
```

<details>
<summary>Показать ответ и объяснение</summary>

`1 [7 9] [7 9]`. Ёмкости хватает для записи в общий массив, но длина исходного описания `base` остаётся равной одному.

</details>

### 3. Вывод кода

Чему равны `len("ёж")` и `utf8.RuneCountInString("ёж")`?

<details>
<summary>Показать ответ и объяснение</summary>

`4` и `2`. Каждая из двух рун в этой строке занимает два байта в UTF-8. Длина строки считает байты.

</details>

### 4. Типичная ошибка

Почему `copy(make([]int, 0, 4), []int{1, 2})` копирует ноль элементов?

<details>
<summary>Показать ответ и объяснение</summary>

`copy` ограничен длиной назначения и длиной источника. У назначения есть запас ёмкости, но нет доступных элементов. Для двух копируемых значений задай длину 2 или расширь срез до неё.

</details>

### 5. Типичная ошибка

Как отличить отсутствующий ключ от ключа со значением `0` в `map[string]int`? Можно ли сразу записать в карту, объявленную через `var m map[string]int`?

<details>
<summary>Показать ответ и объяснение</summary>

Читай через `value, ok := m[key]`. В обоих случаях значение может быть нулём, а `ok` показывает присутствие ключа. Чтение из nil-карты допустимо, запись вызывает панику. Для записи создай карту через `make` или литерал.

</details>
