# Структуры, указатели и методы

## Цель

Научиться объединять данные в структуру и понимать, когда метод работает с копией, а когда меняет исходное значение. Это пригодится перед конкурентностью: важно различать независимые копии и общее состояние.

Нужно знать переменные, функции, возвращаемые значения и `if`. Перед этим уроком пройди [функции](../03-functions/README.md), затем [коллекции и память](../04-collections-and-memory/README.md).

## Как запустить

Из корня репозитория:

```bash
go run ./00-fundamentals/05-structs-and-methods
go test -v ./00-fundamentals/05-structs-and-methods
```

Перед запуском попробуй предсказать, какие задачи станут выполненными.

## 1. Структура объединяет данные

```go
type Task struct {
    Title string
    Done  bool
}
```

`Task` — новый тип с двумя полями. Литерал `Task{Title: "Learn structs"}` задаёт название, а пропущенное поле `Done` получает `false`.

У `var empty Task` все поля имеют нулевые значения: `Title == ""`, `Done == false`. В этом примере задача без названия допустима; проверку названия мы не вводим.

## 2. Присваивание копирует структуру

```go
original := Task{Title: "Learn structs"}
copied := original
copied.Title = "Learn methods"
```

Название `original` останется прежним. Поля этой структуры — `string` и `bool`, поэтому изменение копии не меняет исходную задачу.

Копирование структуры не означает глубокого копирования всех данных. Если добавить поле со слайсом, map или указателем, копии могут обращаться к общим данным — как в предыдущем уроке о коллекциях.

## 3. Метод с получателем-значением

```go
func (t Task) WithTitle(title string) Task {
    t.Title = title
    return t
}
```

Часть `(t Task)` называется получателем метода. Внутри `WithTitle` переменная `t` содержит копию задачи. Метод возвращает её с новым названием; исходная задача остаётся прежней. Возвращённое значение нужно сохранить, чтобы использовать изменение.

`Status()` тоже получает значение: он только читает `Done` и возвращает `"pending"` или `"done"`.

## 4. Метод с получателем-указателем

```go
func (t *Task) Complete() {
    t.Done = true
}
```

`*Task` — тип указателя на задачу. Выражение `&original` получает адрес переменной. Через указатель метод меняет исходную структуру. Для доступа к полю Go позволяет писать `t.Done` вместо `(*t).Done`.

Для переменной `original` можно вызвать `original.Complete()`: Go автоматически использует её адрес. Но не у каждого выражения можно взять адрес; например, результат `Task{Title: "Read"}.Complete()` так вызвать нельзя.

В программе после `pointer.Complete()`:

```text
Original: done
Copy: pending
```

Два указателя на одну задачу видят одно состояние. Отдельная копия структуры остаётся независимой.

## Ограничения и связь с конкурентностью

- Нулевое значение структуры и `nil`-указатель различаются. `var task Task` можно использовать; вызов `Complete()` через `var pointer *Task` вызовет панику. Метод требует ненулевой указатель.
- Указатель позволяет менять состояние, но не синхронизирует доступ. Если несколько горутин читают и изменяют одну задачу без синхронизации, возможна гонка данных. Этот пример выполняется последовательно.
- Получатель-значение не гарантирует независимость вложенных слайсов, map и указателей.
- Повторный `Complete()` оставляет задачу выполненной. Метод не переключает состояние обратно.

## Попробуй самостоятельно

1. Добавь поле `Priority int`. Какое у него нулевое значение?
2. Напиши `Reopen()` с получателем-указателем и тест на повторный вызов.
3. Убери `*` у получателя `Complete`. Сначала предскажи результат, затем запусти тесты: какие проверки обнаружат ошибку?
4. Создай два указателя на одну задачу. Измени её через первый и прочитай состояние через второй.
5. Добавь поле `Tags []string` и проверь, что произойдёт после копирования структуры и изменения элемента слайса. Как получить независимую копию тегов?

## Что проверяют тесты

Нулевое состояние, оба результата `Status`, переименование без изменения оригинала, пустое и русское название, сохранение остальных полей, изменение через указатель, повторное завершение и независимость копии.
