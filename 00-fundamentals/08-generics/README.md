## 1. Параметр типа и вывод аргумента

```go
func first[T any](values []T) (T, bool) {
    if len(values) == 0 {
        var zero T
        return zero, false
    }
    return values[0], true
}
```

`T` — параметр типа. `any` допускает любой тип, а операции ограничены тем, что корректно для всех таких типов. Мы можем индексировать `[]T` и вернуть элемент. Сравнение двух произвольных `T` через `==` компилятор отклонит.

При `first([]int{0, 20})` Go выводит `T = int`. Результат имеет тип `int`, поэтому утверждение типа не нужно. Вызову `first(nil)` информации для вывода недостаточно. Используй `first[string](nil)` или передай типизированный пустой слайс.

Пара `T, bool` различает настоящий ноль и пустой вход. `var zero T` создаёт корректное нулевое значение для подставленного типа.

## 2. comparable и равенство

`contains[T comparable]` сравнивает элементы через `==`. В примере сравниваются строки и числа. Тест подставляет структуру со сравнимым полем. Слайс как непосредственный тип элемента этому ограничению не удовлетворяет.

Интерфейсный тип, например `any`, также допускается как аргумент для `comparable` по специальному правилу Go. Если внутри таких интерфейсных значений окажутся несравнимые значения одного динамического типа, сравнение на этапе выполнения может вызвать панику. Для конкретных типов вроде `string` этот риск отсутствует. Для пользовательского понятия равенства можно принимать функцию сравнения как явный аргумент.

## 3. Упорядоченные типы

`minValue[T cmp.Ordered]` требует упорядоченные числа или строки. `first` помогает отдельно обработать пустой слайс, а `cmp.Less` используется для выбора минимума.

Для чисел с плавающей точкой `cmp.Less` считает NaN меньше обычных чисел. Тест фиксирует это договорённое правило. Если в конкретной задаче NaN следует игнорировать или считать ошибкой, обработку нужно задать явно.

Ограничение поддерживает именованные типы с подходящим базовым типом. Например, `type score int` работает в `minValue`, и возвращаемое значение сохраняет тип `score`.

## 4. Сохранение именованного типа слайса

```go
func reversed[S ~[]E, E any](source S) S
```

`~[]E` разрешает типы, базовый тип которых — слайс элементов `E`. Для `Scores` компилятор выводит `S = Scores` и `E = int`. Поэтому результат всё ещё имеет метод `Count()`.

Функция создаёт отдельный массив, разворачивает порядок элементов и оставляет исходный слайс в прежнем порядке. Нулевой слайс остаётся нулевым, а созданный пустой слайс остаётся ненулевым. Копирование поверхностное: указатели и вложенные слайсы внутри элементов могут по-прежнему ссылаться на общие данные.

## Как выбрать ограничение

| Что делает функция | Что ей требуется |
|---|---|
| Получает первый элемент | `any` |
| Ищет значение через `==` | `comparable` |
| Ищет минимум | `cmp.Ordered` |
| Возвращает прежний именованный тип слайса | Отдельный `S` с ограничением `~[]E` |

Если функция вызывает конкретные методы разных реализаций, часто достаточно небольшого обычного интерфейса. Параметр типа полезен, когда одна схема работы применима к нескольким типам и важен конкретный тип результата.

## Что увидишь и что проверяют тесты

Программа покажет настоящий ноль, пустой список строк, поиск по двум типам, минимумы чисел и строк, а также развёрнутый `Scores` с сохранённым методом. Тесты покрывают пустые данные, сравнимую структуру, NaN, именованные типы и независимость массива результата.

## Самопроверка

Сначала ответь самостоятельно. Затем раскрой ответ и сравни объяснение со своим.

### 1. Понимание

Почему `first[T any]` может взять элемент из `[]T`, а `contains` ограничивает `T` через `comparable`?

<details>
<summary>Показать ответ и объяснение</summary>

Индексация слайса работает для любого типа элемента. `contains` сравнивает два значения типа `T` через `==`, поэтому ограничение должно разрешать именно такое сравнение. Например, слайс можно сравнить с `nil`, но нельзя сравнить два слайса через `==`.

</details>

### 2. Вывод кода

Что напечатает `fmt.Println(x, ok, emptyOK)` после `x, ok := first([]int{0})` и `_, emptyOK := first[int](nil)`?

<details>
<summary>Показать ответ и объяснение</summary>

`0 true false`. Первый ноль является реальным элементом. Пустой вход тоже возвращает нулевое значение типа, а признак `false` отличает его от данных.

</details>

### 3. Вывод кода

Что напечатает `fmt.Println(got, got.Count())` после `got := reversed(Scores{1, 2, 3})`?

<details>
<summary>Показать ответ и объяснение</summary>

`[3 2 1] 3`. Ограничение `~[]E` позволяет вывести `S = Scores`. Возвращаемый `S` сохраняет метод `Count`.

</details>

### 4. Типичная ошибка

Почему `first(nil)` не компилируется, а `first[string](nil)` компилируется?

<details>
<summary>Показать ответ и объяснение</summary>

Нетипизированный `nil` не сообщает компилятору тип элементов. Во втором вызове `T` задан явно, и параметр получает нулевой слайс `[]string`.

</details>

### 5. Типичная ошибка

Что случится с `contains[any]([]any{[]int{1}}, []int{1})`?

<details>
<summary>Показать ответ и объяснение</summary>

Вызов допустим на этапе компиляции, потому что интерфейсный тип `any` может удовлетворять `comparable`. При сравнении два интерфейса содержат значения одного несравнимого динамического типа `[]int`, поэтому возникает паника. Для слайсов нужен подходящий предикат.

</details>
