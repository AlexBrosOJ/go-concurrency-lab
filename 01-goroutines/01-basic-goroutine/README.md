# Базовая горутина

## Что изучаем

В этом примере мы знакомимся с горутинами — основой конкурентного выполнения кода в Go.

Горутина позволяет запустить функцию так, чтобы она выполнялась независимо от текущего потока выполнения программы.

## Как запустить

Из корня репозитория выполни:

```bash
go run ./01-goroutines/01-basic-goroutine
```

Возможный вывод (задержка не гарантирует завершения горутины):

```text
Main: started
Goroutine: hello!
Main: finished
```

## Как это работает

### 1. Обычный вызов функции

```go
sayHello()
```

При обычном вызове функция выполняется в текущей горутине. Программа ждёт её завершения, прежде чем перейти к следующей инструкции.

### 2. Запуск горутины

```go
go sayHello()
```

Ключевое слово `go` запускает вызов функции в отдельной горутине.

При этом программа не ждёт, пока функция завершится, а продолжает выполнять следующие инструкции.

Важно: запуск горутины не означает, что она обязательно начнёт выполняться немедленно или завершится раньше основной функции.

### 3. Почему нужен `time.Sleep`

```go
time.Sleep(100 * time.Millisecond)
```

В этом примере `Sleep` временно задерживает завершение `main`, чтобы горутина успела вывести сообщение.

Если убрать задержку, программа может завершиться раньше, чем `sayHello` выполнится.

Когда функция `main` завершается, процесс заканчивает работу вместе с остальными горутинами. Go не ждёт их автоматически.

**Важно:** `time.Sleep` здесь используется только для демонстрации. В реальном коде ожидание завершения горутин организуют с помощью механизмов синхронизации, например `sync.WaitGroup`, или каналов — их изучим дальше.

## Попробуй самостоятельно

1. Убери `go` перед `sayHello()`. Что изменилось?
2. Верни `go` и убери `time.Sleep`. Всегда ли выводится сообщение горутины?
3. Запусти программу несколько раз. Одинаков ли порядок сообщений?
4. Создай функцию `sayNumber`, которая выводит число, и запусти её через `go`.

## Что нужно запомнить

- Горутина — лёгкий механизм конкурентного выполнения в Go.
- Ключевое слово `go` запускает вызов функции в новой горутине.
- Порядок выполнения горутин не гарантирован.
- Завершение `main` завершает программу, даже если другие горутины ещё работают.
- `time.Sleep` не является надёжным способом синхронизации.

## Следующий шаг

Научимся запускать несколько горутин и правильно дожидаться их завершения с помощью `sync.WaitGroup`.

## Самопроверка

Сначала ответь самостоятельно. Затем раскрой ответ и сравни объяснение со своим.

### 1. Понимание

Чем `go sayHello()` меняет выполнение по сравнению с обычным вызовом?

<details>
<summary>Показать ответ и объяснение</summary>

Обычный вызов выполняется в текущей горутине, которая ждёт его возврата. С `go` тело начинает выполняться в отдельной горутине, а вызывающая может сразу продолжить.

</details>

### 2. Вывод кода

В каком порядке напечатаются строки, если в `main` этого урока заменить `go sayHello()` на `sayHello()` и убрать `Sleep`?

<details>
<summary>Показать ответ и объяснение</summary>

`Main: started`, `Goroutine: hello!`, `Main: finished`. Несмотря на слово «Goroutine» в тексте, функция в этом варианте вызывается синхронно.

</details>

### 3. Вывод кода

Какие строки гарантированно останутся, если убрать только `Sleep`?

<details>
<summary>Показать ответ и объяснение</summary>

Обе строки из `main` гарантированы в порядке «started», затем «finished». Строка из `sayHello` может появиться после первой строки, в том числе после второй, или не успеть появиться до выхода программы.

</details>

### 4. Типичная ошибка

Почему увеличение `Sleep` до секунды не гарантирует, что работа закончится?

<details>
<summary>Показать ответ и объяснение</summary>

Задержка ждёт заданное время и ничего не проверяет о состоянии фоновой работы. Если завершение важно, нужен явный сигнал, например канал или `WaitGroup`.

</details>

### 5. Понимание

Должна ли новая горутина сразу получить отдельное ядро процессора?

<details>
<summary>Показать ответ и объяснение</summary>

Нет. Планировщик Go может чередовать исполнение нескольких горутин даже при выполнении Go-кода на одном ядре. `go` разрешает конкурентное выполнение без обещания одновременной работы на разных ядрах.

</details>
