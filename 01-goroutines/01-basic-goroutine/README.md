# Базовая горутина

## Что изучаем

В этом примере мы знакомимся с горутинами — основой конкурентного выполнения кода в Go.

Горутина позволяет запустить функцию так, чтобы она выполнялась независимо от текущего потока выполнения программы.

## Как запустить

Из корня репозитория выполни:

```bash
go run ./01-goroutines/01-basic-goroutine
```

Ожидаемый вывод:

```text
Main: started
Goroutine: hello!
Main: finished
```

## Как это работает

### 1. Обычный вызов функции

```go
sayHello()
```

При обычном вызове функция выполняется в текущей горутине. Программа ждёт её завершения, прежде чем перейти к следующей инструкции.

### 2. Запуск горутины

```go
go sayHello()
```

Ключевое слово `go` запускает вызов функции в отдельной горутине.

При этом программа не ждёт, пока функция завершится, а продолжает выполнять следующие инструкции.

Важно: запуск горутины не означает, что она обязательно начнёт выполняться немедленно или завершится раньше основной функции.

### 3. Почему нужен `time.Sleep`

```go
time.Sleep(100 * time.Millisecond)
```

В этом примере `Sleep` временно задерживает завершение `main`, чтобы горутина успела вывести сообщение.

Если убрать задержку, программа может завершиться раньше, чем `sayHello` выполнится.

Когда функция `main` завершается, процесс заканчивает работу вместе с остальными горутинами. Go не ждёт их автоматически.

**Важно:** `time.Sleep` здесь используется только для демонстрации. В реальном коде ожидание завершения горутин организуют с помощью механизмов синхронизации, например `sync.WaitGroup`, или каналов — их изучим дальше.

## Попробуй самостоятельно

1. Убери `go` перед `sayHello()`. Что изменилось?
2. Верни `go` и убери `time.Sleep`. Всегда ли выводится сообщение горутины?
3. Запусти программу несколько раз. Одинаков ли порядок сообщений?
4. Создай функцию `sayNumber`, которая выводит число, и запусти её через `go`.

## Что нужно запомнить

- Горутина — лёгкий механизм конкурентного выполнения в Go.
- Ключевое слово `go` запускает вызов функции в новой горутине.
- Порядок выполнения горутин не гарантирован.
- Завершение `main` завершает программу, даже если другие горутины ещё работают.
- `time.Sleep` не является надёжным способом синхронизации.

## Следующий шаг
