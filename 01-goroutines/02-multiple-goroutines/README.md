# Несколько горутин

## Что изучаем

В этом примере мы запускаем несколько горутин, которые выполняют одну функцию независимо друг от друга.

Цель — понять, что конкурентное выполнение не гарантирует определённый порядок выполнения инструкций.

## Как запустить

Из корня репозитория выполни:

```bash
go run ./01-goroutines/02-multiple-goroutines
```

## Как это работает

### 1. Одна функция — несколько горутин

```go
go printNumbers(1)
go printNumbers(2)
go printNumbers(3)
```

Мы трижды запускаем одну и ту же функцию, передавая ей разные идентификаторы.

Каждый вызов выполняется в отдельной горутине. Поэтому три цикла могут продвигаться независимо друг от друга.

### 2. Конкурентное выполнение

```go
for i := 1; i <= 5; i++ {
    fmt.Printf("Worker %d: %d\n", workerID, i)
    time.Sleep(100 * time.Millisecond)
}
```

Каждая горутина выводит пять чисел. Пауза помогает наблюдать, как сообщения разных горутин перемешиваются.

Не следует считать, что Go обязан сначала выполнить весь цикл первого воркера, затем второго и затем третьего.

### 3. Почему порядок меняется

Планировщик Go распределяет выполнение горутин. На фактический порядок влияют планирование, доступность процессорного времени и другие обстоятельства.

Важно различать:

- **Конкурентность** — несколько задач находятся в процессе выполнения и могут продвигаться независимо.
- **Параллелизм** — несколько задач действительно выполняются одновременно на разных процессорных ресурсах.

Конкурентная программа не обязательно выполняется параллельно.

### 4. Почему `time.Sleep` — временное решение

В конце `main` мы используем задержку, чтобы программа не завершилась слишком рано.

Однако время выполнения не гарантировано. Если горутины не успеют завершиться за указанное время, программа всё равно закончится.

В следующем примере мы решим эту проблему с помощью `sync.WaitGroup`.

## Попробуй самостоятельно

1. Запусти программу несколько раз и сравни порядок вывода.
2. Измени количество воркеров с трёх на пять.
3. Измени количество чисел, которые выводит каждый воркер.
4. Удали `time.Sleep` из `printNumbers`. Изменился ли порядок сообщений?
5. Удали `time.Sleep` из `main`. Почему часть сообщений может пропасть?

## Что нужно запомнить

- Несколько горутин могут выполнять одну и ту же функцию.
- Порядок выполнения горутин не гарантирован.
- Конкурентность и параллелизм — разные понятия.
- `time.Sleep` не гарантирует завершение запущенных горутин.
- Для корректного ожидания завершения горутин нужны механизмы синхронизации.
