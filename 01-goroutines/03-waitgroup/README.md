# WaitGroup

## Что изучаем

В этом примере мы учимся ждать завершения нескольких горутин с помощью `sync.WaitGroup`.

В отличие от `time.Sleep`, `WaitGroup` позволяет дождаться фактического завершения задач, а не просто выждать определённое количество времени.

## Как запустить

Из корня репозитория выполни:

```bash
go run ./01-goroutines/03-waitgroup
```

## Как это работает

### 1. Создание WaitGroup

```go
var wg sync.WaitGroup
```

`WaitGroup` — примитив синхронизации из стандартной библиотеки Go. Он позволяет одной горутине дождаться завершения определённого количества задач.

### 2. Регистрация задачи

```go
wg.Add(1)
go printNumbers(workerID, &wg)
```

`Add(1)` увеличивает счётчик на единицу. Мы сообщаем `WaitGroup`, что появилась ещё одна задача, завершения которой нужно дождаться.

Важно вызывать `Add` до запуска горутины, чтобы избежать ситуации, когда `Wait` начнёт ожидание до регистрации задачи.

### 3. Сигнал о завершении

```go
defer wg.Done()
```

`Done()` уменьшает счётчик на единицу.

`defer` откладывает вызов до завершения функции. Поэтому даже если мы добавим в функцию несколько инструкций `return`, отложенный вызов всё равно выполнится.

В нашем примере каждый воркер вызывает `Done()` ровно один раз.

### 4. Ожидание завершения

```go
wg.Wait()
```

`Wait()` блокирует текущую горутину, пока счётчик не станет равен нулю.

В нашем случае `main` продолжит работу только после завершения всех трёх воркеров.

## Типичные ошибки

### Забыли вызвать Done

Если задача увеличила счётчик через `Add`, но не вызвала `Done`, ожидание может никогда не завершиться.

### Вызвали Add слишком поздно

Не стоит запускать горутину, а затем увеличивать счётчик внутри неё. `Wait` может начаться раньше, чем задача будет зарегистрирована.

### Передали WaitGroup по значению

Передавай `WaitGroup` по указателю:

```go
func worker(wg *sync.WaitGroup)
```

Не копируй уже используемый `WaitGroup`: разные копии будут иметь разные состояния счётчика.

### Вызвали Done лишний раз

Если вызвать `Done` больше раз, чем было зарегистрировано задач, счётчик может стать отрицательным и программа завершится с ошибкой.

## Попробуй самостоятельно

1. Убери `time.Sleep` из `main`. Почему программа теперь всё равно ждёт воркеров?
2. Добавь четвёртого воркера.
3. Перенеси `defer wg.Done()` в конец функции. Что может пойти не так, если функция завершится раньше?
4. Временно убери `wg.Done()`. Что произойдёт?
5. Попробуй заменить `wg.Add(1)` перед каждым запуском на один вызов `wg.Add(3)` перед циклом. Почему это тоже работает в данном примере?

## Что нужно запомнить

- `Add` регистрирует количество задач.
- `Done` отмечает завершение задачи.
- `Wait` ждёт, пока счётчик станет равен нулю.
- `WaitGroup` не отменяет горутины и не передаёт им результаты.
- `WaitGroup` сам по себе не защищает общие данные от гонок.
- `Add` нужно выполнять до запуска соответствующей горутины, а `Done` — для каждой зарегистрированной задачи.
