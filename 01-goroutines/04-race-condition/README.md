# Race Condition

## Что изучаем

В этом примере мы знакомимся с гонками данных (data races) в Go.

Гонка данных возникает, когда несколько горутин одновременно обращаются к одной области памяти, хотя бы одна из них выполняет запись, а доступы не синхронизированы должным образом.

## Как запустить

Обычный запуск:

```bash
go run ./01-goroutines/04-race-condition
```

Запуск с обнаружением гонок:

```bash
go run -race ./01-goroutines/04-race-condition
```

Для этого примера используй именно второй вариант. Race detector должен сообщить о конфликтующих обращениях к `counter`.

## Как это работает

### 1. Общая переменная

```go
var counter int
```

Все пять горутин обращаются к одной переменной. Это общая память, а не пять независимых копий счётчика.

### 2. Проблема с counter++

```go
counter++
```

На первый взгляд это одна операция. Однако увеличение счётчика включает чтение текущего значения, вычисление нового и запись результата.

Если несколько горутин выполняют эти действия одновременно, изменения могут конфликтовать, и часть увеличений может потеряться.

### 3. Почему WaitGroup не решает проблему

```go
wg.Wait()
```

`WaitGroup` гарантирует, что `main` дождётся завершения зарегистрированных задач.

Но он не защищает `counter` во время выполнения циклов. Все горутины могут продолжать одновременно изменять переменную.

Синхронизация завершения задач и синхронизация доступа к общим данным — разные задачи.

### 4. Что делает race detector

Флаг `-race` включает инструмент обнаружения гонок данных.

Он отслеживает обращения к памяти во время выполнения программы и сообщает о конфликтующих доступах, если они обнаружены.

В отчёте можно увидеть:
- тип обнаруженной проблемы;
- места чтения и записи общей переменной;
- стеки вызовов горутин, в которых произошли обращения.

Отсутствие сообщения от race detector не доказывает, что во всей программе нет гонок: инструмент анализирует только те участки кода, которые фактически выполнились.

## Попробуй самостоятельно

1. Запусти программу с `-race` и изучи сообщение об ошибке.
2. Измени количество горутин и число увеличений.
3. Удали `wg.Wait()`. Почему теперь `main` может завершиться до окончания работы горутин?
4. Подумай, как исправить гонку с помощью `sync.Mutex`.
5. Подумай, можно ли решить эту задачу через `sync/atomic`.

Не исправляй пример сразу: сначала добейся обнаружения гонки и разберись в отчёте.

## Что нужно запомнить

- Общая переменная может стать источником гонки данных.
- `counter++` не является атомарной операцией.
- `WaitGroup` ожидает завершения задач, но не защищает общую память.
- Race detector запускается с помощью флага `-race`.
- Гонка данных — это не просто случайный порядок вывода сообщений.
- Для защиты общей памяти можно использовать мьютексы, атомарные операции или другие подходящие механизмы синхронизации.
