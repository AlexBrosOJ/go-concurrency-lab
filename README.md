# Go Concurrency Lab

Практический учебный репозиторий по конкурентности в Go, ориентированный на написание кода, подготовку к собеседованиям и обучение новичков.

## Цели проекта

- Изучать конкурентность в Go на практике, самостоятельно пиша и запуская код.
- Разобраться в горутинах, каналах, синхронизации и отмене операций.
- Освоить распространённые паттерны конкурентности и их применение в реальных проектах.
- Подготовиться к собеседованиям на Go Backend-разработчика: от основ до тем уровня Middle.
- Предоставить новичкам понятные примеры, объяснения и практические задания.

## План обучения

План включает как существующие, так и будущие материалы; текущее состояние отражено в таблице выше.

### 00. Основы языка

- Базовый синтаксис, переменные и типы.
- Управление выполнением.
- Функции.
- Коллекции, строки и общая память.
- Структуры, указатели и методы: копирование значений и изменение состояния.

### 01. Горутины

- Запуск горутин.
- Жизненный цикл горутин.
- `sync.WaitGroup`.
- Гонки данных.
- [Замыкания и общее состояние](01-goroutines/05-closures-and-shared-state/README.md): захват переменных, семантика циклов, копии аргументов и синхронизация.

### 02. Каналы

- [Небуферизированный канал](02-channels/01-unbuffered-channel/README.md): передача значения и синхронизация отправителя с получателем.
- [Буферизированные каналы](02-channels/02-buffered-channel/README.md): ёмкость, FIFO, обратное давление и отличие очереди от завершения обработки.
- Отправка и получение значений.
- [Закрытие каналов и `range`](02-channels/03-close-and-range/README.md): конец потока, `ok`, владелец закрытия и несколько участников.
- [Select и таймауты](02-channels/04-select-and-timeouts/README.md): выбор готовой операции, общий срок ожидания и кооперативная отмена.
- [nil-каналы и deadlocks](02-channels/05-nil-channels-and-deadlocks/README.md): отключение веток `select`, завершение потоков и причины блокировок.

### 03. Паттерны конкурентности

- Fan-in — объединение нескольких каналов в один.
- Fan-out — распределение задач между несколькими обработчиками.
- [Pipeline](03-concurrency-patterns/03-pipeline/README.md) — конвейерная обработка, обратное давление и отмена всех стадий.
- [Worker Pool](03-concurrency-patterns/04-worker-pool/README.md) — фиксированное число обработчиков, очередь задач, результаты и отмена.
- [Ограничение параллелизма](03-concurrency-patterns/05-concurrency-limit/README.md) — семафор, допуск до запуска и отменяемое ожидание.
- Сбор результатов параллельных операций.

### 04. Координация и отмена операций

- `context.Context`.
- Отмена операций и установка дедлайнов.
- Корректное завершение работы (graceful shutdown).
- Реализация семафоров.

### 05. Синхронизация

- `sync.Mutex` и `sync.RWMutex`.
- `sync.Once`.
- `sync.Cond`.
- `sync/atomic`.
- `sync.Map`.

### 07. Внутреннее устройство Go

## Как работать с репозиторием

Изучайте темы последовательно, следуя плану обучения.

Для каждой темы:

1. Прочитайте объяснение.
2. Попробуйте предсказать результат до запуска программы.
3. Запустите пример и сравните результат с прогнозом.
4. Выполните практическое задание самостоятельно, используя демонстрационный код как справку. Отдельных решений заданий пока нет.
5. Запустите тесты, если они есть для этого урока.
6. Попробуйте объяснить вслух, как работает реализация и какие у неё есть компромиссы.

## Команды

Запустить пример:

```bash
go run ./03-concurrency-patterns/01-fan-in
```

Запустить все тесты:

```bash
go test ./...
```

Запустить тесты с детектором гонок данных:

```bash
go test -race ./...
```

Эта команда запускает тесты, но не вызывает `main` примеров без тестов. Для демонстрации намеренной гонки запусти отдельно:

```bash
go run -race ./01-goroutines/04-race-condition
```

Ожидаются отчёт race detector и ненулевой код завершения. Отсутствие сообщений при запуске тестов не подтверждает безопасность всех примеров.

Отформатировать Go-код:

```bash
gofmt -w .
```
